BIFROST

The model gateway behind every generation

FreshCode sends generation, evidence assessment and benchmark calls through a Bifrost gateway using its OpenAI-compatible API. The app records the usage the provider reports for each call, so token numbers are measurements rather than guesses.

  • Primary, assessor and fallback model routing
  • Response caching: an identical prompt costs 0 new tokens
  • Retries with timeouts, secrets redacted from every error
  • “Verified” shown only after a real upstream request has succeeded

What you see in the app

Provider input and total tokens, model name, request id and latency on every run, each labelled measured. Local counts are labelled estimated.

What you see in the app

Source titles, URLs, publication dates when the provider returns them, a trust tier per domain, relevance scores and the Tavily request id for each retrieval.

TAVILY

The research and freshness layer

Before generating, FreshCode asks Tavily for current references so the model works from what is true today, not from training data. The same search powers claim checking.

  • Live retrieval with cached repeats
  • Trust tiers: primary, reputable, community, unclassified
  • Graceful degradation: a failed search is reported, never hidden

CONTEXT COMPRESSION

A bounded context, not a pasted web page

Retrieved pages are stripped of boilerplate, deduplicated and ranked sentence by sentence against your task. The result is trimmed to a context budget you control per project.

Measured, not promised

The Evaluation Lab runs paired baseline versus compressed calls on the same model and sources in alternating order, then reports provider-measured input tokens, latency and a raw CSV. Samples are small, so results are directional.

CODE VERIFICATION

Tests run. Failures are reported as failures.

Generated Python and JavaScript tests run for real. If they fail, the failure output goes into one compact repair prompt, and the repair is accepted only if it is strictly better. A stage that fails shows its real failure state.

Execution modes

Docker mode runs code in a disposable container with no network and a read-only filesystem. The local runner enforces limits but is not a sandbox, and the app says so wherever it is used.

FRESHNESS INTELLIGENCE

Catch answers that quietly went stale

Paste any technical answer. FreshCode extracts the claims most likely to change, retrieves current sources and flags newer versions it finds in the evidence. Suggested corrections are labelled as suggestions, with the sources one click away.

Version-drift detection is a heuristic. It never presents an uncertain finding as definitive.

FAQ

Straight answers

Is the no-key demo real?

The search results and sample code are labelled fixtures for a fictional SDK. Evidence compression, version-drift detection and the test run execute live, right now.

How is the token saving measured?

Gateway-reported input tokens, paired runs in alternating order, same model. Three pairs on one task is directional. If the gateway returns no usage, the app claims no saving.

How accurate is stale-claim detection?

It is a heuristic. The built-in self-check uses small hand-written sets, so treat the numbers as optimistic. Always confirm on the official source.

Is running generated code safe?

Only in Docker mode, which this project implements but which must be verified on your Docker host. The local runner is defence in depth, not a sandbox, and execution is off by default in production.

Which languages are tested automatically?

Python (pytest) and JavaScript (node:test, needs Node.js). Other languages are generated but not executed.
